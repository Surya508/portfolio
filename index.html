Async Notification Fan-Out (CompletableFuture)
NotificationDispatcher.java
@Service
public class NotificationDispatcher {
 
  private final Executor ioPool;
  private final List<Channel> channels;
 
  public CompletableFuture<DispatchResult>
      fanOut(NotificationEvent e) {
 
    var futures = channels.stream()
      .filter(c -> c.supports(e.persona()))
      .map(c -> CompletableFuture
        .supplyAsync(() -> c.send(e), ioPool)
        .exceptionally(ex -> Failure.of(c, ex)))
      .toList();
 
    return CompletableFuture
      .allOf(futures.toArray(CompletableFuture[]::new))
      .thenApply(v -> DispatchResult.aggregate(futures));
  }
}
Persona-routed parallel dispatch (Push, In-app, Email) with isolated failure — one slow channel can't block the rest. Powers 1M+ daily notifications.
Cassandra TTL Notification Store
NotificationRepository.java
@Repository
public class NotificationRepository {
 
  private static final String INSERT = """
    INSERT INTO notifications (
      tenant_id, user_id, ts, payload)
    VALUES (?, ?, ?, ?) USING TTL ?
  """;
 
  public void save(Notification n) {
    int ttlSeconds = (int) Duration
      .between(Instant.now(), n.expiresAt())
      .getSeconds();
 
    session.execute(prepared.bind(
      n.tenantId(), n.userId(),
      n.timestamp(), n.payload(),
      ttlSeconds));
  }
  // Partition: (tenant_id, user_id), Cluster: ts DESC
}
Per-row TTL means expired notifications self-clean — no batch jobs, no tombstone storms. Read-pattern matches the partition key. Scales horizontally with the user base.
Debezium CDC → RabbitMQ (Dual-Write)
CdcOutboxRouter.java
@Component
public class CdcOutboxRouter {
 
  @KafkaListener(topics = "dbz.user_events",
    groupId = "outbox-router")
  public void onChange(DebeziumEvent evt) {
 
    if (!evt.isCreateOrUpdate()) return;
 
    var domainEvent = mapper.toDomain(evt.after());
 
    // Idempotent publish — outbox table dedupes
    rabbit.convertAndSend(
      "users.exchange",
      domainEvent.routingKey(),
      domainEvent,
      msg -> {
        msg.getMessageProperties()
           .setMessageId(evt.lsn().toString());
        return msg;
      });
  }
}
Captures DB changes via Debezium → Kafka → re-publishes to RabbitMQ for legacy consumers. LSN as message-id keeps the dual-write path idempotent during migration.

A snapshot of the engineering choices & trade-offs behind the platforms I've shipped.

JVM Performance Engineering
Profiled hot paths with async-profiler & JFR; eliminated GC stalls and CPU hotspots. Migrated Tomcat → Undertow on a non-blocking IO layer for higher concurrency at lower memory.

Multi-Tenant Architecture
Tenant ID as a first-class header, propagated via interceptors → service layer → repository filters. Schema-per-tenant for sensitive isolation, shared-schema with row-level filter for the rest.
RBAC · Tenant Isolation

High-Throughput Notifications
Cassandra wide-row with TTL handles millions of writes/day per tenant; Redis Streams act as an in-memory feed cache for the bell-icon endpoint — sub-50ms reads.
Cassandra · Redis · Kafka

CDC + Dual-Write Migration
Debezium streams MySQL binlog → Kafka. Outbox-router publishes domain events to RabbitMQ for legacy consumers. LSN as message-id makes the path idempotent — survives replays.
Debezium · Kafka · RabbitMQ

Distributed Caching Layers
Redis as the cross-service cache, Hazelcast for in-process near-cache. Cache-aside on hot reads, write-behind for non-critical paths. TTL + manual eviction on writes prevents stale data.
Redis · Hazelcast · Cache-Aside

Event-Driven Microservices
Kafka for high-throughput pipelines & replay; RabbitMQ for low-latency RPC-style flows. Schema registry + contract tests prevent breaking changes between teams.

Secure Payments Integration
Razorpay webhook with HMAC signature verification; idempotency keys on every charge; audit log table for regulatory replay. Full PII masking in logs.
